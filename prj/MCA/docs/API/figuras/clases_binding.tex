% El binding de Python sobre libmca: un handle de Python por bloque, cada uno
% dueño de su handle de C, y el despacho de las funciones públicas.
%   arriba     las funciones <bloque>_*(h, …) con @_api, que miran h._via y van a
%              libmca, a la referencia en Python o a la red; a la derecha, la
%              referencia; a la izquierda, _libmca.py, lo común del binding
%              (cargar el .so, traducir los códigos a excepciones, Bus y Mem);
%   al medio   los handles de los bloques con referencia (MCA, Osciloscope, las
%              dos fachadas del multitrigger, Integration) y el shim
%              MultiTriggerScope;
%   abajo      los dos que existen sólo en C, sin @_api ni referencia:
%              OsciloscopeRing y GenPulsos; y los envoltorios de los lazos, que
%              están en clases_lotes.
% Los métodos que son una función de C no se repiten: están en clases_libmca.
% El proxy de red (MCARemote) está en clases_red; los sustitutos de prueba no
% se dibujan (diseno_de_clases.md §5.1).
% Fuentes: software/API/{_despacho.py,_libmca.py,mca.py,osciloscope.py,
% multitrigger.py,integration.py,osciloscope_ring.py,generadores.py},
% software/multitrigger_utils.py. El texto que acompaña está en
% docs/API/libmca.md §5; el epígrafe, en clases_binding.txt. Estilo:
% docs/figuras/estilo_tikz.tex y clases_estilo.tex.
%
% Compilar:   pdflatex clases_binding.tex
%             pdftocairo -svg clases_binding.pdf clases_binding.svg
%
