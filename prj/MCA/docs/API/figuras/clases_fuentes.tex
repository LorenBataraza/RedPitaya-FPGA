% Las fuentes de eventos del osciloscopio: la interfaz EventSource, por lote, y
% sus dos implementaciones sobre la placa. Arriba, quién llama cada parte del
% contrato: AcquisitionSession lee la forma del evento y llama arm, close y
% meta, una vez por corrida; ReaderThread llama read_batch y lee pending, una vez
% por lote. Al medio, BramSource y RingSource, que cumplen la interfaz sin
% heredar. Abajo, lo que cada una usa: el lazo de C (Lector o LectorRing, en
% clases_lotes), el ring, y el shim con que arman el disparo.
% El camino por evento del lector (wait_event, snapshot, read_into, rearm) ya no
% lo usa ninguna fuente sobre la placa: sólo el sustituto de prueba, que no se
% dibuja (diseno_de_clases.md §5.1).
% Fuentes: software/API/osciloscope_store/sources.py (la interfaz, BramSource),
% software/API/osciloscope_ring.py (RingSource), reader.py y session.py (quién
% llama qué). El texto que acompaña está en docs/API/adquisicion_de_eventos.md
% §1; el epígrafe, en clases_fuentes.txt. Estilo: docs/figuras/estilo_tikz.tex y
% clases_estilo.tex.
%
% Compilar:   pdflatex clases_fuentes.tex
%             pdftocairo -svg clases_fuentes.pdf clases_fuentes.svg
%
